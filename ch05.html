第5章

Skill で手順を再利用する

Lv4 仕組みにする目安 3時間

毎回 AI に頼んでいる手順を「Skill」という形にまとめて、何度でも使えるようにします。

この章のゴール

  • Rules と Skill の違いが分かる
  • 簡単な Skill を1つ作り、次の周で使える

Rules と Skill の違い

Rules = いつも守る約束(AGENTS.md)
Skill = 決まった仕事をするときの手順

どれを Skill にする?

毎周 AI に送っている頼み方の中から選びます。一番長いものから作ると、1行で済むようになるのがすぐ分かります。多くの人は次の2つです。

  • review-plan … 相談役の PR のブランチに切り替えて、plan.md を今のコードと照らして見直し、止まる
  • check-before-finish … 「できました」と言う前に確かめて報告する
「できました」と言う前に
1. intent.md と spec.md を読む
2. 変更したところ(差分)を見る
3. テストを実行する
4. エラーが出ていないか見る
5. spec.md の条件を1つずつ確かめる
6. 結果を報告する

やること

  1. 1つ目は、講師が渡す見本の中身のまま、AI に置いてもらう。置き場は .agents/skills/<名前>/SKILL.md
  2. 見本を読む。上の --- の間の description は「いつ使うか」の名札です。これを読んで、AI が自分で使うかを決めます
  3. 2つ目は「1つ目と同じ形で」と、いつ使うかと手順だけを伝えて、AI に作ってもらう
  4. AGENTS.md に同じ手順が書いてあれば、Skill の名前の1行に置きかえて短くしてもらう
  5. 使ってみる。名前で呼ぶときは、Antigravity は /名前、Codex は $名前 です。名前を書かずに頼んでも、AI が自分で使うことがあります(使わなければ、次から名前を書きます)
  6. 次の周も、Skill の名前と実装の文だけで回せたら、この章はおしまい

作った Skill は、その周のブランチに入れて、いつもの PR と一緒にマージします。

良い頼み方を書く → 良い仕事のやり方を仕組みにする

権限(AI に渡す鍵)

読むだけ → 任せる
ファイルを変える・コマンドを動かす → 確認してから
危ないこと → させない

Skill で AI に任せる仕事が増えるので、AI に何をさせてよいかも決めておきます。設定は、講習で講師と画面を見ながら一緒にやります。

  • まず「させない」ことを決めます。たとえば、GitHub の記録を強制的に上書きする(force push)、フォルダをまるごと消す、など。AI はうまくいかないときに「消してやり直そう」とすることがあるからです
  • 「任せる」は、何度も許可を押したものだけを、少しずつ増やします

アプリの中で AI を使う人だけ

AI の答えの出来を測る仕組み(Eval)を足します。それ以外の人はテストだけで大丈夫です。
