第6章

自動テストと自動公開

Lv5 自動で回す目安 3時間

PR を出すたびにテストとレビューが自動で走り、マージしたら自動で公開される状態を作ります。あわせて、API キー(サービスを使うための合言葉)の作り方と守り方を学びます。

この章のゴール

  • PR やマージのたびに、テストと公開が自動で走るのを体験する
  • API キーの作り方と守り方が分かる

流れ

PR を出す → 自動でテスト(CI) → マージ → 自動で公開(CD)
しくみすること
GitHub ActionsPR のたびに、テストを自動で走らせる
自動レビューPR を出すと、run-gemini-cli が自動でレビューを付ける
GitHub Pagesmain にマージしたら自動で公開する(公開する人だけ。Web で作った人は作ったものを、そうでない人も public なら第3章の紹介ページを公開できる)

API キーの約束

自動レビューには Gemini の API キーが要ります。

  • 作るのは自分です(Google AI Studio で作ります)
  • ファイルに書かない。GitHub の Secrets(リポジトリに合言葉を隠して置く場所)に入れる
  • 画面に映さない・チャットに貼らない。AI にも渡さない
  • 漏れたかもしれないと思ったら、すぐに消して作り直す
  • 無料枠で送った内容は、Google の改善に使われることがあります。private のリポジトリで使うかは講師と決めます

やること

  1. AI に GitHub Actions の設定を作ってもらい、PR でテストが走ることを確かめる。private の人は、秘密情報を見つける仕組み(gitleaks)も入れてもらう
  2. API キーを作り(自分で行う)、GitHub の Secrets に入れる。AI に run-gemini-cli の設定を作ってもらい、PR に自動でレビューが付くことを確かめる
  3. (公開する人)GitHub Pages を設定してもらい、マージで公開されることを確かめる
  4. わざとテストが落ちる PR を出し、PR の画面に ✗ が出ることを確かめる
    • public の人: 「テストが通らないとマージできない」設定を入れる
    • private の人: GitHub が止めてくれないので、✗ ならマージしない を約束にする
  5. わざと偽のパスワードのような文字を入れた PR を出し、止まる・✗ になることを確かめる(確かめたら消す)

マージしてよい条件(ここから先)

  1. CI(自動テスト)が通っている
  2. AI レビューに「重大」の指摘が残っていない
  3. 自分で 実際に触って spec.md の条件を全部確かめた
  4. 「講師を呼ぶとき」に当たらない

公開したものは誰でも見られる。個人情報・秘密情報が入っていないかを、もう一度確かめる。
