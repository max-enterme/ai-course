第2章

作りたいものを言葉にして、プロジェクトの説明書を作らせる

Lv0 作ってもらう目安 3時間

作りたいものを言葉にして、AI に最初の仕事として「プロジェクトの説明書」を作ってもらいます。できたら GitHub に上げます。

この章のゴール

  • 作りたいものを、使う人の目線で数行で言える
  • AI に README.md と AGENTS.md を作らせ、自分で開いて読み、直してもらえる
  • AI が AGENTS.md を読んでいるかを、新しい会話で確かめられる
  • 作業フォルダを GitHub に上げ、GitHub の画面で見られる

プロジェクトの説明書とは

ファイル誰が読むか書くこと
README.md自分・講師・相談役の ChatGPT何を作るか(最終像)
AGENTS.md作る役の Antigravity(毎回自動で読む)AI が守る約束

最初に説明書を置いておくと、このあと AI に頼むときの文が短くなり、AI の出来も安定します。説明書は日本語なので、頼んだとおりかを自分で読んで判断できます。

流れ

作りたいものを話す → 空のフォルダを開く → AI に説明書を作らせる → 自分で開いて読む
→ 直してもらう → 新しい会話で約束を言わせて確かめる → GitHub に送る → GitHub の画面で見る

1つ頼む → 開いて確かめる → 次を頼む の順で進めます。毎回、必ず自分でファイルを開きます。

やること

1. 作りたいものを言葉にする

講師と話して、メモ帳に数行でまとめます。作り方(使う技術など)は決めません。

考えること例(ToDo アプリ)
誰が使うか / いつ・どこで使うか自分が、朝の支度の前にスマホで
何をしたら、何が出たら嬉しいかやることを入れると一覧に出て、終わったら消せる
今はどうしていて、何が面倒か紙に書いているが、なくす
やらないこと他の人との共有・通知

最終像は途中で変わってもかまいません。変わったら README.md を直してもらいます。

2. 空のフォルダを開く

第1章で作ったフォルダを Antigravity で開き、何も入っていないことを自分の目で見ます。

3. README.md を作ってもらう

メモを貼って頼みます。できたら開いて読み、1か所直してもらい、開き直してそこだけ変わったかを見ます。

このフォルダに README.md を作ってください。
下のメモを元に、次の見出しで短くまとめてください:
何を作るか / 誰が・いつ使うか / 使うとどうなるか(最終像) / 今はどうしていて、何が面倒か / やらないこと
- 作り方(使う技術・画面の細かい作り)は書かないでください
- メモに無い機能を足さないでください
- 作ったら、中身をそのまま見せてください

メモ:
<話してまとめたメモ>

4. AGENTS.md を作ってもらう

講師から、あなたの作るものに合わせた AGENTS.md の文面を受け取ります(下は Web で作る場合の例です)。

# このプロジェクトで守ること

- 何を作るかは README.md に書いてある。README.md に無い機能は作らない。足したほうがよいと思ったら、作る前に聞く
- 作り: HTML / CSS / JavaScript だけで作る。ライブラリや追加のインストールは使わない。index.html をブラウザで開けば見られる形にする
- ファイルは index.html / style.css / script.js の3つを基本にする。増やすときは先に聞く
- `docs/` は、作るものを紹介するページの置き場。ここだけは作りの約束とは別に、HTML / CSS だけで index.html と style.css の2つにする
- 頼まれていないところ(見た目・文章・ファイル)は変えない
- 本名・住所・連絡先・顔写真・パスワードをファイルに書かない。実在の人の名前は仮の名前にする
- 説明は初心者にも分かる短い日本語で。専門用語にはその場で一言説明を付ける
- 終わったら、どのファイルに何を書いたかと、どう確かめたかを報告する。確かめていなければ、そう書く

頼み方:

このフォルダに AGENTS.md を作ってください。中身は下の文をそのまま使ってください。
作ったら、中身をそのまま見せてください。

<上の型を、作りの行を埋めて貼る>

5. AI が約束を読んでいるか確かめる

Antigravity で新しい会話を開いて送ります。ファイルの名前は出しません(「AGENTS.md を読んで」と言うと、自動で読んでいるかどうかが分からなくなるため)。

このプロジェクトで、あなたが守ることになっている約束を3つ言ってください。
何を作るプロジェクトかも1文で言ってください。
  • AGENTS.md に書いたとおりの約束が出れば OK
  • ファイルを探し始めた・「分からない」と答えたときは、講師に伝えます

6. 頼んでいないファイルが増えていないか見る

増えていたら消してもらいます。消す前に 許可 を求められるのを見てください。

7. GitHub に送る

  1. GitHub で新しいリポジトリを作る。名前は英数字。README を付けずに空のまま作る
    • 作ったものを Web で公開するなら public、決まっていなければ private(あとから切り替えられます)
  2. 講師を collaborator(一緒に作業する人)に招待する
  3. Antigravity に頼む
このフォルダを Git でセーブ(commit)して、GitHub の <リポジトリの URL> に送って(push して)ください。
- 送るのは README.md と AGENTS.md だけです。他のファイルがあれば、送る前に教えてください
- 終わったら、何をしたかを初心者向けに説明してください
  • 初めて送るときは、ブラウザで GitHub へのログインが出ます。ログインは自分で行います(パスワードを AI に渡さない)

8. GitHub の画面で見る

リポジトリの画面を開き、README.md の中身が表示されていることを自分で見ます。第1章の地図に戻って、「今、ローカルからリモートに送った」と確かめます。

自分で確かめること

AI が「作成しました」「送りました」と言っても、自分でフォルダ・ファイル・GitHub の画面を開きます。

  • 頼んだ名前のファイルが、頼んだフォルダに本当にあるか
  • 中身が、自分が話したことになっているか(話していない機能や作り方が足されていないか)
  • 頼んでいないファイルが増えていないか
  • GitHub の画面に、送ったはずのファイルがあるか

会話の分け方

  • 話題が変わったら、新しい会話を開きます。前の話が混ざるほど、答えがずれやすくなります
  • 伝えることは、小出しにせず1回にまとめて送ります

約束

説明書は GitHub に上げます。public なら誰でも見られます。

本名・住所・学校名や勤め先・電話番号・メールアドレス・顔写真を書かない。ニックネームで書く。一緒に使う友だちなど、実在の人の名前も書かない。
